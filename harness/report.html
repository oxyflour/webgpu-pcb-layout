Cypress 布局 Harness 报告

2026-10-05 · 目标（AGENTS.md）：设计 harness，使 dsh agent 调用工具得到的 PCB 布局指标（布通网络数、过孔数、HPWL）接近人工水平。布局器只用 NVIDIA Cypress。

布通网络数6 块板均有运行达到人工
HPWLpico、edk、acc 全部低于人工；k60、ppc-n3 最好一次低于人工；ppc-n1 高 12–15%
过孔数（主要差距）pico 已持平人工；acc 高 8–11%，edk 高 33–44%，k60 约 2 倍
相对单独 Cypress所有板、三项指标全部更好；主要来自工具，agent 在 acc、k60 上再明显提升

1. 方法

  • 布局器：只用 Cypress（镜像 cypress:20261004，RTX 3090 Ti），不使用 WebGPU 布局器或 LNS。每个候选的流程：起始布局 → Cypress → 共享 0.1 mm 合法化器 → benchmark 路由评估（板子实际层数，0.4 mm 网格）。
  • agent：dsh headless（DeepSeek Flash），通过 pcb 命令行工具操作。命令有 info（含 --section ics）、map（ASCII 布局图）、check（检查位置是否被占用、给出最佳旋转）、place（运行 Cypress 并评估）、inspect、submit。agent 只决定 IC 的位置和旋转。
  • 评估：每次评估都跑 3 个 dsh，并行执行；每次工具调用都限制在 3 分钟内。最终提交的布局用完整路由重新评估，并做严格几何检查（无重叠、不越界、不进禁布区、固定器件和所在面不变）。
  • 可复现性：同一评估协议下，harness 的 Cypress 调用复现了历史 benchmark 中 pico seed 1000 那一行（71/86 布通、273 过孔、HPWL 1861 mm），结果完全一致。

5. 速度与正确性修复

  • Cypress 每轮迭代都为日志计算一次交叉数：跳过之后，acc 优化器时间 122 s → 6.5 s，结果完全相同。
  • 关闭交叉项、冻结旋转：k60 单次 Cypress 59 s → 16 s，质量相当。
  • 并发控制：最多 3 个 Cypress 任务，每个 6 线程（12 核机器）。place 超时不计入 agent 的预算。check 每次会话限 60 次（曾有 agent 用脚本循环调用约 250 次）。
  • ppc（约 2000 器件、10 层）：工具内用增量路由（146 s → 44 s，过孔 +0.8%）并设截止时间。单次 place 约 80–120 s，不超过 3 分钟。
  • 合法化器网格取整在 ppc 上留下 3–16 µm 的微小重叠，已加后处理推开，最终布局全部合法。

6. CPU 路由加速：试了哪些、结论如何

在 ppc-n3 上测量，信号网络 1607 个，网格 738×375×10 层。最慢的 100 个网络（多为跨板的两脚长线）占 66% 的时间。

加权 A*（w = 1.5），只用于 agent 循环内与精确路由逐个相同（33/33 个候选）过孔 ×1.08–1.13（中位 1.10）；按"布通优先、再看过孔"排序的 Spearman 相关 0.998；6 次会话中 5 次选出的最佳候选相同，另 1 次过孔只差 0.5%单独运行 46 s → 20 s已采用（>1000 器件的板），最终评估仍用精确路由

GPU 路由：仓库里的 src/gpu/grid-router.js 只是单层、单网络的距离场原型，不能直接替代评估路由器。根本问题是：GPU 只有在很多网络同时布线时才快，而上表说明这样做在 ppc 上不收敛，或者因为网络都挤在 BGA 周围而无法并行。另外路由器是混沌的，只改一处浮点加法顺序，ppc 的过孔数就从 8802 变成 8739，所以最终评估必须用 CPU 精确路由。可行的用法是做粗网格的 GPU 排序代理；在这之前，加权 A* 已经能提供类似的加速。

7. 剩余差距与下一步

  • 过孔是主要差距：pico 已持平人工（56–60 vs 59），edk 比人工高 33–44%，k60 约 1.7–2.2 倍，acc 高 8–11%，ppc 高 9–19%。acc 的差距完全来自电源轨去耦电容的摆放；k60 的差距来自小器件链和各次运行之间的波动（IC 规划不稳定）。
  • k60 运行间波动：最好一次 318/318，另外两次约 300。最好的那次 U302（以太网 PHY）的位置和旋转都对了。
  • 下一步：
    1. 加权 A* 已在 ppc 的工具内启用（评估 44 s → 20 s），下一轮用它重跑 ppc，预计每次会话的 place 次数大约翻倍。
    2. 研究电源轨去耦电容和小器件链的可推导规则，降低过孔。
    3. 分析 ppc 上 agent 增益很小的原因（36 个 IC 规划不过来，还是 place 次数太少）。
    4. 补测 ppc-n1 的单独 Cypress 基线。
