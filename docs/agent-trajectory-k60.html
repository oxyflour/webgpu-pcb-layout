2. 逐步说明

① 摸底：agent 只读不改

会话开始前，工具已经用空 plan 生成了 c000（不占 agent 预算）。agent 第 11 秒就看清了局面：c000 已经布通全部 318 个信号网络，但过孔 487，人工 310。所以后面所有尝试都围绕“降过孔”展开。它随后读了 8 颗 IC 的引脚分布（哪一侧引脚连到谁）、c000 的拥塞区和设计约束（3 组关键网络、55 个去耦电容）。

关键分工：agent 只给 8 颗大件（≥8 引脚：U201 MCU、U302 以太网 PHY、U1301/U1302、U402 RS232、U901、U701/U702 DIN 缓冲）定位置和转角。另外 396 个小件全部由工具算法摆放。

② check：便宜的试算

pcb check 只做“起始布局 + 合法化”，约 1 s，不跑 detail pass，也不布线。它回答两件事：shiftMm 表示想放的位置是否撞到固定件、禁布区或其他 IC，撞到时要挪多远；anchoredHpwlByRotation 是这颗 IC 在 4 个转角下连到已定位件的线长。agent 用它在 Plan A 之前修正了 U302/U901/U1301 的坐标，又在 c002 之后确认所有 IC 的转角都已最优。

③ place：一次调用的流水线

  1. 起始布局（lib/start-layout.mjs）：plan 里的 IC 放到指定位姿。from: cXXX 时，其余所有件沿用该候选的版图。from: centroid 时，每个小件放到它所连引脚的加权平均位置，权重为 1/对方引脚数（人工习惯把小件放在引脚较少的那个伙伴旁边），再朝伙伴转 90° 的倍数。
  2. 合法化：0.1 mm 间距，消除重叠和出界。本轨迹每次平均只挪 0.05–0.19 mm。
  3. detail pass：见第 3 节。
  4. 布线评估：原生网格布线器（0.4 mm 网格，PathFinder 式协商，最多 40 轮）。布线器对网格相位很敏感，所以同一版图在 5 个相位偏移下各布一次，取中位数，并报告 min–max 噪声区间。k60 每个相位约 2 s，5 个并行。
  5. 回报：clean / vias / HPWL、噪声区间、overflowRound1（第 1 轮拥塞总量，越低说明余量越大）、收敛相位数、失败的关键网络、去耦电容距离。工具自动判定是否为新最优。

④ 搜索过程

  • c001：从零按 agent 自己的完整平面图（Plan A）摆放。过孔降到 475，但掉了 2 个网络。agent 随即换策略：在 c000 上只改一个因素。
  • c002：只把 U1302/U901/U702 的转角改对，过孔 487 → 447。这是整条轨迹里唯一一次大幅提升。
  • c003–c011：在 c002 上逐个试 IC 平移和转角（U201 移动或转 180°，DIN 缓冲、PHY、RS232 搬家），全部变差。最差的是 U201 转 180°，过孔 551，丢了 15 个网络。
  • c012：U302 微移到 (26.5, 46)。过孔同样 447，但 overflowRound1 从 595 降到 574，收敛相位从 3/5 升到 4/5，按平局规则成为新最优。
  • c013–c016：围绕 U302 微调，外加一次原 plan 重跑（c015：444），都没有明显胜出。agent 提交了 c012。

3. detail pass 在干嘛

代码：harness/lib/detail.mjs（JS 版）和 harness/native/detail.cpp（C++ 版，结果一致，快约 10 倍）。它是位于合法化和布线之间的小件局部优化器，对象是 396 个可动、少于 8 引脚的件（电阻、电容、二极管等）。IC、固定件和通孔件都不动。

每次尝试：随机挑一个小件，做一种动作

动作每次尝试中被选中的概率（%）具体做法
relocate（跳到伙伴旁）15跳到它所连其他引脚的均值 ±1.5 mm。去耦电容则跳到其所属 IC 的电源引脚旁。
shift（平移）47上下左右走 0.4 / 0.8 / 1.2 / 2 mm
rotate（旋转）21转 90° / 180° / 270°
swap（交换）17与 6 mm 内同尺寸的小件互换位置

只接受合法的动作（不重叠、保持 0.1 mm 间距、不出界）。接受与否看代价变化 Δ：

cost = Σ 加权 HPWL + 2 × 通道缺口 + 0.5 × 去耦电容距离 + 关键网络走廊罚分

  • HPWL：所有网络的半周长线长（mm）。有约束的关键网络权重 ×4。
  • 通道缺口：这一项最关键，直接针对过孔。对每对相邻、属于不同件和不同网络、在同一层的焊盘，若间隙小于 0.8 mm，就记 (0.8 − 间隙)。0.4–0.8 mm 的缝在 0.4 mm 布线网格上能否穿过一根线取决于网格相位，所以这些缝正是布线器被迫打孔绕行的地方。参考：人工 k60 有 161 对这样的焊盘，早期工具版图有 598 对。
  • 去耦电容距离：电容电源焊盘到所属 IC 最近电源焊盘的距离（mm）。
  • 关键网络走廊：关键网络引脚之间直线走廊里每出现一个异网焊盘，罚 4 分，目的是让 USB 等网络能不打孔直连。

Δ < 0 就接受；Δ > 0 时以 exp(−Δ/T) 的概率接受（模拟退火）。T 从 3 几何降到 0.003，按尝试次数或时间预算的进度计算。之后再合法化一次。

结论：从零起步时，detail pass 自己就贡献了 −94 个过孔、+4 个布通网络、−1000 mm HPWL。c000 基线的质量几乎全部来自它。agent 的 IC 改动在此之上又降了 40 个（487 → 447）。

值得注意的一点：即使 from: c002，detail pass 也会从高温重新退火，把 c002 里已经优化好的小件重新洗一遍（372/396 个被移动，201 个改了转角）。所以两个候选的差异 = IC 改动 + 小件重新退火的随机性 + 布线相位噪声。同一个 plan 重跑（c012 → c015）就差了 3 个过孔，c012 自己 5 个相位之间更是跨 54 个。agent 的大部分微调（c013–c016）落在这个噪声里，很难判断真假。可能的改进：from 已有候选时，detail pass 用低起始温度，或只在被改动的 IC 附近重排，让 agent 的比较更干净。
