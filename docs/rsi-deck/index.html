1 · 基本思路

Agent = LLM + Harness；外层 Agent 优化内层 Agent 的 Harness

LLM 是固定的，能改的是 Harness：给它看什么（prompt / skill / memory）、给它什么手（tool / MCP / CLI）、谁来规划和验收（planner / verifier）。

  • AI4AI 的一个用法：外层 Agent 不直接解题，而是改进内层 Agent 解题用的 Harness。
  • Prompt：外层 Agent 从轨迹里总结的人工布局经验，写成内层 Agent 能执行的规则。
  • Tool：外层 Agent 写代码，改接口、改算法、修 bug，每次调用控制在 3 分钟以内。
  • Verifier：评分本身也是被优化的对象。评分噪声太大时，好的 prompt 也选不出来。

2 · 场景：自动布局

三个关键指标怎么算：布通网络数、过孔数、HPWL

每个候选布局都先过同一个合法化器，再用同一个布线器真实地布一遍线，指标从布线结果里读出来。HPWL 不需要布线。

布通网络数（个，越多越好）

在 0.4 mm 网格上，用板子自己的层数做 PathFinder 协商布线：所有网络先各自走最短路，再逐轮给拥挤格加价重布，最多 40 轮。

结束时一条信号网络所有引脚都连通，且不与别的网络共用格子，才算布通。占用冲突（overflow）或没连上（open）都不算。

过孔数（个，越少越好）

布线在相邻两层之间每换一次层，记 1 次层间切换。本片中的“过孔”默认就是层间切换数，对全部信号网络的布线求和。

在 10 层的 ppc 板上，一个贯穿孔最多会被记 9 次，所以另外统计物理过孔：同一格上叠在一起的切换只算 1 个。双层板上两者相同。

HPWL（mm，越短越好）

对每个信号网络，取它所有引脚的外接矩形，记半周长 w + h；把所有信号网络的半周长加起来就是 HPWL。电源和地网络不计，各网络权重相同。

它不需要布线、算得最快，是布局器优化的主目标。但它衡量不了绕线和换层：k60 上 Agent v7 的 HPWL 只比人工高约 16%（6711 vs 5799 mm），过孔却多了约 69%（489 vs 289）。

去噪：同一个布局只平移 0.01 mm，布线结果就会变（见“评分器降噪”一页）。所以工具、人工目标和最终评估都把网格整体平移若干个相位（5 个；超过 1000 件的板 3 个），在 worker 线程里各布一遍，取中位数，并报告最小—最大的范围。实现见 harness/lib/board.mjs 的 evaluate / evaluateRobust。

总结

结论与下一步

  • RSI 循环有效，但瓶颈不在 prompt。迭代 12 个 prompt 版本后，同一版本会话之间的差距仍然大于版本之间的差异。
  • 起点是最关键的模块。只用网表推导的起点，在 13 板上把过孔从 2.4–4.0 倍降到 1.3 倍。关键信息依次是：IC 的位置、面、旋转，然后是小件靠近引脚更少的伙伴。
  • 工具速度决定 Agent 能试几次。一个会话里放置调用占 76% 的时间；布线器在 ppc 上从 151 s 降到 6.9 s。
  • 评分器也要被优化。单次路由的噪声（±15 条网络）会把 prompt 之间的比较全部淹掉。
  • 剩下的差距是过孔（k60 557 vs 345，pic 492 vs 363），集中在 IC 周边小件的精确排布上。
  • 下一步：用当前工具在 13 板 + ppc 上重跑 agent sweep，统一口径；第 17 页用的是旧数据。

展望 · RSI 的将来演进

被改进的对象逐层上移：产物持续改进 → 复杂问题规划 → 反思和策略探索

三种常见 RSI 框架共享同一条纪律：Agent 只负责提议，Host 用预先固定的 verifier 在全新的工作树里验收；Agent 自己报告的结果不算证据。

VeriLoop：产物持续改进

清华 SIGS，VeriLoop E2 技术报告（2026）。核心是生成和验收分离，模型不能自证进步。

从当前最优出发→提议一个候选→外部验证→不回退 + 至少一项严格变好：提交否则回滚，并把拒绝原因反馈给下一轮

结构：单链爬山，每轮 1 个 Agent；成本随迭代数线性增长。

适用场景：有确定性 verifier 的单一产物，比如修代码、补推导、调一个配置。

在 PCB 上：把 refine 链的接受规则改成“鲁棒评分下布通数不回退、过孔或 HPWL 严格变好”，并且由 Host 而不是 Agent 判定。现在的 refine 链是 Agent 自己挑。

Raven：复杂问题规划

EverMind AI，arXiv 2609.33439（2026-09），“Harness 的 Harness”。

Planner 拆成 DAG→按能力派给不同 Agent 并行执行→集成→整体验收失败：记入记忆，重新规划

结构：每轮一张图，没有改动的节点直接复用缓存；论文中还有 harness 自进化和技能库。

适用场景：需要多个专家协作的复合任务（研究、代码、设计、值班）；单个 Agent 做不完的任务。

在 PCB 上：按模块拆（MCU、电源、接口、存储），由不同 profile 并行布局，再集成成全板做验收。在 ppc 这类 2000+ 件的板上，单个 Agent 只做了 4–8 次 place 就自行停止了（预算是 16 次）。

Dream-RSI：反思和策略探索

UMD · Google DeepMind · UVA，arXiv 2609.14858（2026-09）。关键洞察：已积累的发现历史本身就是一个回放模拟器。

在线：策略驱动 Agent 扩展发现树（贵）→离线“做梦”：在历史树上回放，改写 policy（便宜）→回放分严格更高：换上新策略

结构：发现 Agent 和评估器都固定，只改“扩展哪个节点、并行几个、何时停”。论文在 Lasso 任务上把调用数从 550 降到 317。

适用场景：需要成千上万次“提议-评估”的长程发现任务，比如算法、数学优化、GPU kernel。

在 PCB 上：会话 75–78% 的时间花在放置调用上。可以把 v1–v12 的轨迹和布局树当回放语料，离线优化“何时新开 floorplan、何时 refine、何时停”。
